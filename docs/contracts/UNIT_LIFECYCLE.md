## 등록과 재사용

1. `StageController.Start`는 씬에 연결된 활성·생존 플레이어를 등록한다. 필드가 바뀌면 살아 있는 기존 플레이어를 입구로 옮긴다.
2. 웨이브·소환은 `SpawnEnemy`를 통해 풀에서 적을 꺼낸다. 사전 배치 적은 필드 생성 후 활성화한다. 활성화 시 `Health.OnEnable`은 현재 체력을 최대치로 초기화한다.
3. `InitEnemy`는 `Enemy.Init`에 공유 생존 플레이어 목록을 넘긴다. `RegisterUnit`이 필드·집계 여부를 기록하고 `Health.Died`를 구독한다. AI에 스테이지와 스폰 통지를 전달하고 사망 연출 완료를 구독한다. AI는 활성화 후 첫 행동 전에 한 프레임을 기다린다.

### 공용 스테이지 실행

- `TryStartRun`은 공용 `StageData`와 활성·생존 플레이어 목록을 받는다. 솔로는 1명이고 멀티는 호스트가 출발 시점의 참가자를 등록한다. 씬 전환 후 플레이어는 해당 씬에서 새로 생성한다.
- `FieldChanged`는 새 필드의 인덱스와 초기 진행 상태를 함께 읽을 수 있는 시점에 발행한다. HUD의 필드별 대사·적 표시·보스 잔상은 필드 종료 시 정리한다.
- `RunFinished`는 실행마다 한 번 발행한다. `Cleared`는 확정된 최종 클리어의 복귀, `PartyDefeated`는 보통 필드에서 등록 파티 전원의 HP 0, `Aborted`는 클리어 전 스테이지 검증 실패 또는 참가자 이탈이다. 보통 필드에서 플레이어가 빈사에 진입하면 생존 목록에서 빠지고, 구조되면 목록에 돌아온다. 전원 HP 0은 빈사 만료를 기다리지 않고 전멸로 처리한다.
- 호스트 흐름은 결과를 받아 StageController를 비활성화해 필드·적·탄·구독을 정리하고 전투 씬을 해제한다. 방을 유지한 채 거점으로 돌아가 Ready를 초기화한다. 클라이언트는 호스트가 통지한 필드와 네트워크 스폰 상태를 반영한다.

- [StageCatalogData](../../Assets/_Project/Scripts/Stage/StageCatalogData.cs)는 고정 `StageId`로 StageData를 찾고 초기 개방 목록을 제공한다. 호스트는 ID와 레디 버전을 검증해 출발 데이터와 인원을 고정한다. 게스트는 자신의 카탈로그에서 같은 ID를 조회해 준비를 확인한다. 콘텐츠와 네트워크 메시지 형식이 같은 빌드를 사용한다.

### 동적 스폰 필드

- `StageField`의 `EnemySpawner`를 지정하면 중앙 입장과 준비 발판을 사용한다. 호스트가 입장한 플레이어 각각의 발판 점유를 검사한다. 전원이 서로 다른 발판에 올라선 상태가 1초 지속되면 발판을 숨기고 전투 시계를 시작한다.
- `CurrentHuntPhase`는 준비 종료 시 오후로 시작한다. 호스트가 집계 대상 적의 누적 처치 수를 기준 처치 수와 저녁·한밤 비율에 대조한다. 경계를 넘을 때 `HuntPhaseChanged`를 발행하며, 게스트는 통지받은 상태를 같은 계약으로 읽는다. 새 필드와 전투 씬 해제 시에는 이전 상태를 비운다. 호스트의 `HuntEnemySpawned`는 개체 등록을 마친 적과 생성 시 시간대를 전달한다. 시야·조명·강화 실행은 이 상태와 이벤트를 구독하는 기능이 맡는다.
- 단계별 테이블은 별도로 지정할 수 있다. 비어 있는 저녁·한밤 테이블은 이전 테이블을 이어 쓰고, 새 테이블이 선택되면 단계 시각을 다시 센다. 각 테이블의 `SpawnData.StartTime`은 적용 시점 기준이다. 일반 적 목록의 수량은 플레이어 한 명의 링에서 한 번에 요청하는 수다. 시계 방향 급습은 9시·12시·3시·6시 단계마다 같은 수량을 요청한다. 테이블 또는 웨이브가 바뀌면 이전 순차 단계를 취소한다.
- `requiredElites`는 시작 시간대와 전체 수량을 가진다. 지정 시간대 이후 정원과 스폰 위치 조건이 허용될 때 시도하며, 생성에 성공한 수만 예정 수량에서 차감한다. 일반 웨이브보다 먼저 시도한다.
- `SpawnRadius`는 플레이어 중심 스폰 원의 단일 반경이다. 협공·화살촉에서는 반경이 대형의 기준점이다. 후보 생성과 위치 검증을 분리한다. NavMesh에 보정한 뒤 적의 캡슐을 감싼 바운드가 최초 추적 대상 플레이어의 카메라 프러스텀에 겹치면 후보를 제외한다. 다른 플레이어의 화면에는 스폰이 보일 수 있다. 호스트는 자신의 실제 카메라와 원격 플레이어 위치에서 재구성한 원격 프러스텀을 사용한다. 캡슐 겹침 검사도 적용한다. 일반 웨이브의 실패한 위치와 정원 초과 수량을 다음 웨이브로 이월하지 않는다.
- 생성 기준 플레이어는 각 적의 수명 기록에 남긴다. 어그로가 바뀌어도 그 플레이어의 정원을 사용하며, 적 사망 시 정원을 반환한다. HP 0인 플레이어의 링은 쉬고 구조되면 재개한다. 적 패턴의 소환은 정화 점수에서 제외한다.
- 사전 배치와 계획된 등급을 함께 본다. 보스가 최고 등급인 필드는 보스 전부, 엘리트가 최고 등급인 필드는 엘리트 전부, 일반만 있는 필드는 `purificationGoal`을 처치한다. 시간대 진행은 최고 등급에 관계없이 집계 대상 적을 사용하고, 패턴으로 소환한 적은 두 집계에서 제외한다.
- 중간 필드의 목표에 도달하면 전투를 잠그고 신규 웨이브와 기존 공격을 정리한다. 호스트가 다음 필드로 이동하면 전투 잠금을 해제한다.
- 마지막 필드의 목표에 도달하면 생존 플레이어들의 중앙에 포털을 생성하고 `GameEvents.StageCleared`를 한 번 발행한다. 신규 웨이브는 중지되고 이미 생성된 적과 공격은 계속 동작한다. 중앙이 보행 불가 위치면 생존 플레이어 위치를 사용한다. 생성 때 이미 겹친 플레이어는 한 번 나갔다 다시 들어온다. 포털 진입 또는 개방 후 전멸이면 `RunFinished(Cleared)`를 한 번 발행해 거점으로 복귀한다.

### 보스 필드

- StageField에 연결한 보스 프리팹과 스폰 지점마다 호스트가 보스를 한 번 생성한다. 프리팹은 Boss 등급과 Unit, Health, NavMeshAgent가 필요하다. 위치는 지점에서 0.5m 이내의 해당 에이전트 NavMesh에 보정하고 지점의 회전을 사용한다. 멀티는 등록된 NetworkObject와 EnemyNetworkState가 필요하다.
- 보스 필드는 동적 스포너를 연결하지 않는다. 준비 발판과 웨이브는 일반·엘리트용 필드에 적용한다. 보스는 SpawnEnemy로 등록하고 기존 BossSpawned에 따라 HUD를 표시한다.
- 연결한 보스와 필드에 미리 배치한 보스를 모두 처치하면 필드를 클리어한다. 중간 보스 필드는 호스트가 다음 필드로 이동하고, 최종 보스 필드는 포털로 거점에 복귀한다.

- 보스 최대 HP는 참가 확정 인원의 StageData 배율과 UnitData 기본 HP를 곱한다. 호스트는 Spawn 전에 보정값을 준비하고, 게스트는 현재·최대 HP를 같은 스냅샷으로 적용한다. 풀 재사용은 다음 스폰의 초기값에서 시작한다.
- 솔로 보스전은 개인 HP를 사용한다. 협동 보스전은 참가자 기본 최대 HP 합계에 공유 계수를 곱해 팀 체력을 초기화한다. 피격자의 실드를 먼저 차감한 후 팀 체력을 차감한다. 팀 체력이 0이 된 타격의 초과 피해는 버리고, 각 플레이어는 자신의 기본 최대 HP에 마지막 숨 계수를 곱한 개인 풀로 전환한다.
- 마지막 숨을 소진하면 귀신이 되어 적 추적 대상에서는 빠지고 이동과 공격을 계속할 수 있다. 공통 공격 판정은 귀신의 최종 피해에 0.3을 곱한다. 전원이 귀신이면 패배하며, 이미 확정된 보스 페이즈 전환 중에는 복귀까지 전멸 판정을 보류한다.
- 보스의 페이즈 완료 시 HP와 팀 체력을 회복하고 귀신을 복귀시킨다. 실드에는 기존 잔량을 유지한다. 마지막 숨은 권한이 있는 쪽에서 `Health.Heal`로 회복할 수 있다. 공유 체력 활성 중에는 이 호출을 차단한다. 흡수 발동·상한은 플레이어 전투에서 정한다.
- 호스트의 `StageController.SharedBossHealthDamaged`는 실제 팀 체력 감소량을 전달한다. 표시 쪽은 `PlayerLife.SharedBossHealth`와 `SharedBossHealthChanged`, `PlayerLife.State`와 `StateChanged`를 사용할 수 있다.

## 피해와 사망

- 공격 판정은 `Hurtbox` 레이어의 피격용 Collider에서 부모의 `IDamageable`을 찾는다. 같은 부위가 공격에도 쓰이면 공격용 Collider와 피격용 Collider를 별도 GameObject에 배치한다. 근거리 패턴은 공격용 Collider만 켜고 끈다. 이동용 Collider는 기존 레이어를 사용한다.
- 평타와 자동 조준의 `targetLayers`는 피해를 받는 `Unit`의 레이어를 지정한다. 물리 조회에는 `Hurtbox` 트리거를 포함하고, 자동 조준은 대상 `Enemy.Rank`로 보스 우선순위를 판단한다. 평타는 장판과 같은 영역 조회로 부채꼴에 걸친 Collider를 찾고, 한 번 휘두를 때 부위당 한 번 피해를 전달한다. `Hurtbox` 컴포넌트가 없으면 `IDamageable`을 단위로 집계한다.
- 원형·부채꼴·도넛은 높이와 실제 곡선 경계를 가진 영역에서 `BoxCollider`, `SphereCollider`, `CapsuleCollider`의 겹침을 계산한다. 도넛 중앙이 안전 구역이며, 판정 높이 안에서 피격 영역이 링의 안쪽이나 바깥쪽 경계에 닿으면 적중한다. 직사각형은 Unity의 `OverlapBoxNonAlloc`으로 조회한다.
- 공격 판정은 적중 시점에 `max(0, 공격력 − 방어력) × 패턴 배율 × (1 − 부위 감소율)`을 계산해 `Health.TakeDamage`에 전달한다. 방어력 기본값은 0이다. 사망 탄막은 사망 시 확보한 공격력으로, 적중한 시점의 대상 방어력을 사용해 계산한다.
- `Health.TakeDamage`는 네트워크에서 HP를 수신하는 개체, 이미 사망한 개체, 무적 상태, 0 이하 피해를 무시한다. 유효한 피해는 활성 실드에 먼저 적용하고 초과분을 HP에서 차감한다. `DamageApplied`는 공격자, 타격 전후 HP와 실제 HP 감소량을, `Damaged`는 실드 차감 후 HP에 들어가는 피해량을 전달한다. 실드만 소모된 타격에는 두 이벤트를 발행하지 않는다. `Kill`은 실드를 거치지 않고 사망을 처리한다.
- `Health.Changed`는 체력 초기화·감소·구조·네트워크 값 변경을 화면에 알린다. 최근 적 HUD는 실제 HP 차감과 별개로 유효하게 접촉한 일반 적을 기록한다. 자세와 어그로는 기존 피해 이벤트를 사용한다. [인게임 HUD 제작 가이드](../IN_GAME_HUD.md)
- `IDamageable.TakeDamage`는 `Ignored`, `Absorbed`(HP 차감 없이 실드만 소모), `Applied`, `Killed`를 반환한다. 결과는 이벤트 구독자 호출 전에 확정한다. 적 패턴의 기존 HP 피격 VFX는 `Applied`와 `Killed`에 예약한다.
- `Shield.Charge`는 설정된 최대치까지만 충전하고 기존 만료 시각을 유지한다. `Shield.SetDuration`은 현재 실드 전체의 만료 시간을 설정하며, `null`은 무기한이다. 스폰·풀 재사용 시 초기값으로 채우고 타이머를 초기화한다. 피해로 잔량이 처음 0이 될 때만 `ShieldBroken`을 발행한다. 만료·사망·회수로 잔량이 사라질 때는 `ShieldChanged`를 사용한다. 멀티의 피해·충전·만료 계산은 권한이 있는 쪽에서 수행한다.
- `Posture`는 비치명 피해량에 자세 피해 배율을 적용한다. 자세가 0이 되면 `GroggyStarted`를 발행하고 그로기 종료 시 최대치로 복구한다. 일반 감소는 유예 시간 이후 설정된 회복 시간에 따라 복구한다.
- [EnemyAggro](../../Assets/_Project/Scripts/Core/EnemyAggro.cs)는 적 개체별로 공격자마다 실제 HP 감소량 × 배율을 누적한다. 공격자 없는 피해나 `Kill`은 어그로를 올리지 않는다. `AddAggro`는 피해 없이 지정한 양을 추가한다. 비활성화·풀 재사용 시 누적 수치를 초기화한다. 배율을 지정할 프리팹은 `EnemyAggro` 컴포넌트를 추가해 설정한다. 별도 설정이 없는 적은 활성화 전에 기본 배율 1을 사용한다.
- 플레이어 사망은 입력·이동·컨트롤러를 끄고 생존 타겟 목록에서 제외한다. 스테이지는 플레이어 본체를 풀로 반환하지 않는다.
- 적 사망 시 `EnemyAI.OnHealthDied`가 행동과 일반 탄을 정리하고 연출을 시작한다. `StageController.OnUnitDied`는 소속 필드와 집계 여부를 확인한다. AI는 한 프레임 뒤 `CanRunDeathPattern`을 확인해 사망 효과를 실행한다. 효과 구성은 [적 패턴 계약](ENEMY_PATTERNS.md)을 참조한다.
- 생존 적을 필드 전환으로 회수할 때는 사망 이벤트가 발생하지 않는다. 사망 연출이 진행 중이면 완료 통지를 받아 본체를 회수한다. AI가 없거나 비활성인 사망 적은 스테이지가 직접 회수한다.

## 필드 전환과 사망 탄막

- 중간 필드 전환과 최종 포털 진입 시 남은 사망 탄막 발사를 중단한다. 생성된 사망 탄을 반환하고, 진행 중인 사망 근거리 판정은 필드 유효성을 확인하며 종료한다. 최종 포털이 열린 동안에는 현재 필드의 사망 공격이 동작한다.
- 본체 회수만으로는 사망 탄막이 중단되지 않는다. 사망 시점에 기록한 위치·방향·공격력으로 발사하고, 이미 생성된 탄도 필드가 열려 있는 동안 계속 동작한다.
- `FinishField`는 생존 적을 회수하고 중간 필드를 제거한다. 필요하면 필드 하위의 사망 연출 중인 적을 스테이지 아래로 옮긴다. 마지막 필드는 포털 이용 또는 전멸로 런이 종료될 때까지 유지한다. 스테이지 중단·비활성화 시에는 `ReleaseStage`에서 사망 탄·기록·필드를 정리한다.

## 회귀 확인

- 공격용 Collider만 겹치면 피해나 조준 대상이 되지 않는다. 피격용 Collider 여러 개가 같은 부위에 속하면 한 번의 평타가 한 번만 적용된다.
- 풀에서 같은 적을 다시 꺼냈을 때 체력과 스폰 패턴이 새 생애로 시작한다.
- 일반 처치와 최종 포털 개방 뒤에는 본체 반환 후 사망 탄막이 이어진다. 중간 필드 클리어와 최종 포털 이용 시에는 남은 발사가 취소되고 기존 사망 탄이 회수된다.
- 웨이브·사전 배치 적과 소환 적을 함께 놓고 집계 차이와 필드 전환 시 회수를 확인한다.
- 플레이어 사망 시 조작이 중단되고 적의 타겟 목록에서 빠진다.
