# 작업·검증 절차

## 작업 순서

1. **조사.** 현재 브랜치·기준 커밋·기존 변경을 확인하고, [문서 색인](INDEX.md)에서 관련 문서를 고른다. 코드 호출부와 실제 씬·프리팹·데이터 연결을 함께 확인한다.
2. **설계.** 사용자에게 보이는 결과, 상태를 변경하는 주체, 생성·해제 순서와 완료 조건을 정리한다. 기존 동작과 변경안을 구분하고, 결과를 바꾸는 미정 사항이 있으면 해당 부분만 확인한다.
3. **구현.** 합의된 범위에서 기존 경로를 재사용한다. 직렬화 필드·형식이 바뀌면 영향을 받는 에셋과 오버라이드를 검색하고 변환 전후 참조를 대조한다.
4. **검증.** 아래 기준에서 변경에 필요한 항목을 고른다. 실행 결과는 실제 대상 브랜치·커밋과 미커밋 변경 범위에 연결한다.
5. **보고.** 변경, 실행한 검증, 미실행·실패, Git 결과를 남긴다. 변경을 커밋할 때는 포함할 경로와 diff를 확인하고, 푸시했다면 원격 커밋을 대조한다.

## 기존 시스템 변경

| 유형 | 판단 기준 | 예시 |
| --- | --- | --- |
| 동작 보존 리팩터링 | 기존 호출 방법, 관찰 가능한 결과와 실행 순서, 상태 소유권, 직렬화 데이터 해석을 유지한다. | 단일·시퀀스의 스텝 해석을 통합하고 보스의 2페이즈 시퀀스가 기존대로 패턴 1 → 2 → 4를 실행한다. |
| 공용 계약 변경 | 호출자나 에셋이 의존하는 입력·결과, 이벤트 순서, 생성·취소·회수 책임 또는 직렬화 형식이 바뀐다. 메서드 이름이나 시그니처가 같아도 이 기준을 적용한다. | 시퀀스 스텝에 페이즈 조건을 다시 적용하거나 필드 전환 시 사망 탄막의 회수 시점을 바꾼다. |

동작 보존 리팩터링은 영향을 받는 시나리오의 기준 동작을 먼저 확인하고, 변경 후 같은 결과가 나오는지 검증한다. 예상 밖의 동작 차이가 발견되면 기존 동작을 복원하거나 아래 계약 변경 절차를 적용한다.

### 공용 계약 변경 절차

1. **영향 범위.** 현재 동작과 변경 후 동작을 각각 한 문장으로 적는다. 호출자·이벤트 구독자, 관련 씬·프리팹·ScriptableObject, 직렬화 필드와 오버라이드를 추적한다. 수명 변경은 생성·취소·회수의 담당자와 순서를 변경 전후로 비교한다.
2. **승인 기준.** 사용자 요청에서 변경 동작과 적용 범위가 명확하면 해당 범위에서 진행한다. 기존 기획 변경이나 데이터 이관처럼 결과에 영향을 주는 선택이 남아 있으면, 현재 동작과 선택지별 영향을 설명하고 해당 부분을 구현하기 전에 결정을 확인한다.
3. **회귀 검증.** 바뀔 동작과 유지할 동작을 각각 검증한다. 수명 변경은 일반 처치·전환을 확정하는 처치·풀 재사용처럼 관련 경로를 Play Mode에서 확인한다. 직렬화 변경은 기존 에셋 참조와 Unity 재임포트 결과를 확인한다. 나머지 검증은 [변경에 맞는 검증](#변경에-맞는-검증)을 따른다.
4. **문서와 PR.** 해당 계약 문서를 같은 변경에서 갱신한다. 패턴 선택·실행·효과는 [적 패턴 계약](contracts/ENEMY_PATTERNS.md), 등록·피해·사망·회수는 [개체 수명 계약](contracts/UNIT_LIFECYCLE.md)에 반영한다. 시스템 간 연결이나 코드 진입점이 바뀌면 [시스템 지도](SYSTEM_MAP.md)도 갱신한다. PR이 있으면 동작의 전후 차이, 데이터 이관 여부, 실제 검증 결과와 미실행 항목을 기록한다.

## 변경에 맞는 검증

| 변경 유형 | 확인할 항목 |
| --- | --- |
| 문서 | 링크, 현재 코드·에셋과의 일치, diff |
| 동작 보존 리팩터링 | 기존 호출자와 직렬화 참조, 컴파일, 영향받는 기존 동작의 회귀 |
| 데이터·프리팹·씬 | GUID와 참조, Unity 임포트, 실제 사용 씬에서의 적용 |
| 게임 동작·수명 | 컴파일과 Console, 관련 Play Mode 경로. 변경에 맞춰 정상·경계·취소·재사용 사례를 선택 |

- 정적 검토, Unity 참조를 사용한 외부 컴파일, Unity Editor 컴파일, Console, EditMode·PlayMode, 사용자 수락을 각각 기록한다. 실행한 자동 검사에는 실행 수와 성공·실패·건너뜀을 적는다.
- 실행 검증을 할 때는 대상 프로젝트와 씬을 확인한다. 필드 진행이 목적이면 [시스템 지도의 씬 연결](SYSTEM_MAP.md#씬과-데이터)을 참조한다. 작업자의 미저장 씬과 Inspector 변경을 보존한다.
- 공유 Unity Editor에서 여러 작업을 진행하는 경우 임포트·컴파일·테스트를 조작할 담당자를 한 번에 한 명으로 맞춘다.

## 인계가 필요할 때

기존 PR·이슈·작업 기록에 다음 정보를 남긴다.

- 목적, 기준 브랜치·커밋, 허용 경로와 보존할 변경
- 완료한 작업, 남은 결정이나 장애, 다음 행동
- 검증 대상과 실제 결과, 재실행 방법, 미검증 범위
- 커밋·푸시·병합 여부와 해당 커밋 또는 PR
